## 1. 프로젝트 개요

### 1.1 목적

파일럿(v1, 멀티페이지 + jsPDF CDN)을 **신표준 아키텍처(단일 파일 SPA, 외부 의존성 0)** 로 재구축한다. URS 16개 항목은 v1과 동일하게 유지한다.

> **재구축 사유**: 협회 교육 환경(수강생 개인 노트북, 회사망 제한 가능)에서 CDN 의존성은 동작 실패 리스크.
> **품질 기준**: 목업이 아닌 실제 구동 가능한 고품질 완성품.

### 1.2 산출물 (4종)

| # | 파일 | 용도 |
|:-:|---|---|
| 1 | `URS.md` | 사용자 요구사항 (16개 항목, v1과 동일) |
| 2 | `FDS.md` | 기능 설계 명세서 (v1→v2 변경점, 추적 매트릭스) |
| 3 | `구현계획서.md` | **본 문서** |
| 4 | `elb.html` | 실습 대상 웹 애플리케이션 (단일 파일 SPA) |

## 2. 시스템 아키텍처 요약

- **유형**: SPA (해시 라우터), 순수 HTML5 + CSS3 + JS (ES2017+), **외부 의존성 0**
- **저장소**: localStorage (prefix `elb:`)
- **인쇄**: `window.print()` + `@media print` (jsPDF 제거)
- **디자인**: Starbucks 디자인 시스템 (LM/COA v2와 동일 표준)
- **특징**: 승인 워크플로우 없음 — **작성 = 전자서명 = 확정** (append-only 불변 기록)

## 3. 구현 단계 (4 Stage)

### S1. 문서 작성 — URS / FDS / 구현계획서
### S2. elb.html — 골격 + 인증 + 패스워드 정책 + 라우터
- Starbucks 테마, 시드 데이터 (Manager 계정 1개, 장비 5종, 정책 기본값)
- 로그인 + 비밀번호 만료 검사 + 강제 변경 화면
- 자동 로그아웃, 라우터 + 권한 가드(Manager/Operator)

### S3. elb.html — 로그 작성(전자서명) + 이력 조회 + 출력
- 로그 작성 폼 (장비 선택/직접입력, 시작/종료, 목적) + 시간 순서 검증
- 저장 = 전자서명 (서명자 + KST 일시)
- 이력 조회 (장비/날짜/작성자 필터) + 장비사용 기록서 인쇄 (출력시간 표시)

### S4. elb.html — 감사추적 + 계정 관리 + 시스템 설정
- 감사추적 (필터 + CSV 내보내기)
- 계정 관리 (Operator/Manager 생성, 정책 강제 검증)
- 시스템 설정 (자동 로그아웃 시간, 패스워드 정책, 장비 목록 관리)
- 본인 비밀번호 변경
