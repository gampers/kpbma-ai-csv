## 1. 프로젝트 개요

### 1.1 목적
URS(16개 항목)에 정의된 시험성적서(COA) 발행 시스템을 **브라우저 단독 실행 가능한 단일 HTML 파일**로 구현하여 CSV 교육 실습에 사용한다. 본 문서는 FDS와 분리되어 **구현 작업의 절차/일정/검증 방법**을 정의한다.

### 1.2 산출물 (3종)
| # | 파일 | 용도 |
|:-:|---|---|
| 1 | `FDS.md` | 기능 설계 명세서 (URS↔FDS 추적 매트릭스 포함) |
| 2 | `구현계획서.md` | **본 문서** — 구현 단계, 일정, 검증, 리스크 |
| 3 | `coa.html` | 실습 대상 웹 애플리케이션 (단일 파일 SPA) |

### 1.3 참조 문서
- `URS.md` (사용자 요구사항 16개 항목)
- `FDS.md` (기능 설계 명세서)

## 2. 시스템 아키텍처 요약

- **유형**: Single Page Application (SPA), 해시 라우터 기반
- **기술 스택**: 순수 HTML5 + CSS3 + JavaScript (ES2017+) — **외부 의존성 0**
- **저장소**: 브라우저 `localStorage` (네임스페이스 prefix `coa:`)
- **빌드/배포**: 없음 — `coa.html` 파일을 브라우저에서 열기만 하면 동작
- **인쇄**: `window.print()` + `@media print` 스타일시트로 COA 출력

> 단일 HTML 파일을 채택한 이유: 빠른 구현, 외부 리소스 의존 없음, 더블클릭 실행 가능, 트레이너의 코드 열람 단순화.

## 4. 구현 단계 (5 Stage)

### S1. 문서 작성 — FDS.md
- **산출물**: `FDS.md` (한국어, 12개 절, URS↔FDS 추적 매트릭스 16행)
- **체크포인트**: 16개 URS 항목 모두 매트릭스에 매핑되어 있고, 각 항목이 하나의 VS-ID와 연결됨

### S2. 문서 작성 — 구현계획서.md
- **산출물**: 본 문서
- **체크포인트**: 5 Stage + VS-01~16 검증 시나리오 1:1 매핑 명시

### S3. coa.html — 골격 + 인증 + 라우터
- **구현 범위**:
  - HTML 골격 + CSS 테마 (Noto Sans KR, 회색/녹색 팔레트)
  - Storage helper, 시드 계정 자동 주입
  - 로그인 화면, 세션 복원, 로그아웃
  - 해시 라우터 + 역할별 라우트 가드
  - 역할별 사이드 내비 + 대시보드
- **체크포인트**: 3개 시드 계정으로 각각 로그인 시 사이드 내비가 다르게 표시됨 (VS-01, VS-02 부분)

### S4. coa.html — 결과 입력 / 워크플로우 / COA / 추적 / 계정관리
- **구현 범위**:
  - 결과 입력 폼 (8필드 필수 검증) — URS 4, 5, 11, 12
  - 내 작성건 / 승인 대기 / COA 출력 목록 화면
  - 결재 액션 (제출 / 승인 / 반려) — URS 3
  - 수정 시 사유 모달 + RecordHistory 적재 — URS 6, 13
  - 승인/출력 후 잠금 — URS 16
  - COA 인쇄 화면 (헤더/본문/서명/푸터) — URS 4-7, 10, 12
  - 문서번호 부여 — URS 14
  - 감사추적 화면 + CSV 내보내기 — URS 9, 10
  - 계정 관리 화면 — URS 2
- **체크포인트**: VS-02 ~ VS-14, VS-16 통과

### S5. coa.html — 환경설정 + 자동 백업 + 정밀도 마감
- **구현 범위**:
  - 환경설정 화면 (`backupTime`, `precisionPct`, 마지막 백업 시각)
  - 수동 백업 / 백업 가져오기 / 데이터 리셋
  - 자동 백업 트리거 (페이지 로드 / 로그인 직후, 멱등)
  - ±1% 정밀도 인라인 + 푸터 표기 — URS 8
- **체크포인트**: VS-08, VS-15 통과 + 16개 시나리오 전체 통과
