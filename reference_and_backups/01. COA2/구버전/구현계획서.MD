# COA 시험성적서 자동판정 시스템 당일 MVP 구현계획 (교육용 데모)

## 요약
1. 목표는 `오늘 수업 내` 동작 가능한 로컬 브라우저 기반 MVP를 완성하는 것입니다.
2. 범위는 `정적 웹앱(Vanilla JS, 무의존성)`이며 `localhost`에서 실행합니다.
3. 핵심은 로그인, 기준설정, 자동판정, 판정 잠금, 보고서(PDF), Audit CSV입니다.
4. 수업 완료 기준은 자동 테스트가 아니라 `시연 성공`입니다.

## 확정된 범위
1. 실행환경은 `Chrome/Edge 최신 + http://localhost`이고 실행 명령은 `python -m http.server 8080`입니다.
2. 사용자/권한은 `고정 admin 단일 계정`입니다.
3. 로그인 정책은 ID/PW, PW 마스킹, `5회 실패 시 1분 잠금`, 자동 로그아웃 `기본 5분(1~30분 설정)`입니다.
4. 시험항목은 `텍스트 1개 + 숫자 1개` 고정입니다.
5. 숫자 규칙은 `min/max` 범위 판정, 입력 소수점 최대 2자리, 표시값 소수점 1자리 반올림, 판정은 `원입력값` 기준입니다.
6. 텍스트 규칙은 허용값 목록 일치이며 `trim + 대소문자 무시`입니다.
7. 부적합 시 사유는 자유서술 `필수`, 적합 시 비활성화합니다.
8. 판정 확정 후 레코드는 완전 잠금이며 수정 대신 신규 레코드 생성입니다.
9. 보고서는 인쇄 전용 새 창에서 `HTML → PDF` 저장합니다.
10. Audit Trail은 앱 내 append 누적 후 `요청 시 CSV Export`합니다.
11. 데이터 저장은 IndexedDB 우선, 실패 시 localStorage 폴백입니다.
12. 실습 데이터 초기화는 설정 탭에서 관리자 수동 실행입니다.

## UI/UX 설계 (단계형 위저드)
1. 로그인 화면: ID/PW 입력, 실패 횟수/잠금 상태 안내.
2. 1단계 기준설정: numeric min/max, 허용 텍스트 목록, 타임아웃 분값 설정.
3. 2단계 결과입력: `sample_id`, `lot_no`, 텍스트값, 숫자값(점/쉼표 모두 허용).
4. 3단계 자동판정: 원값/표시값/판정근거/최종상태(적합·부적합·판정불가) 표시.
5. 4단계 확정: 부적합 사유 검증 후 확정 잠금.
6. 5단계 보고서: 새 창 인쇄뷰 + PDF 저장.
7. 설정 탭: 타임아웃, 데이터 초기화, 감사로그 Export.

## 공개 인터페이스/타입/스키마
1. 신규 저장 타입 `UserAccount`  
`{ user_id: "admin", password_plain: "1234", active: true }`
2. 신규 타입 `CriteriaConfig`  
`{ numeric_min, numeric_max, allowed_texts[], auto_logout_min, updated_at, updated_by }`
3. 신규 타입 `TestRecord`  
`{ record_id, sample_id, lot_no, text_raw, text_norm, numeric_raw, numeric_display, judgement_status, fail_reason, criteria_snapshot, locked, created_by, created_at }`
4. 신규 타입 `SessionState`  
`{ user_id, login_at, last_activity_at, timeout_min, failed_attempts, lock_until }`
5. 신규 타입 `AuditEvent`  
`{ timestamp, user_id, action, target, change_detail, checksum }`
6. Audit CSV 헤더(확정):  
`timestamp,user_id,action,target,change_detail,checksum`
7. 파일명 규칙(확정):  
`COA_{sample_id}_{lot_no}_{yyyyMMdd_HHmmss}.pdf`  
`AUDIT_{yyyyMMdd_HHmmss}.csv`

## 핵심 로직 규격
1. 숫자 파싱은 `,`를 `.`로 정규화 후 파싱합니다.
2. 입력 숫자 자릿수 검증은 소수점 2자리 초과 시 차단합니다.
3. 표시값은 소수점 1자리 반올림, 판정값은 원입력값 유지입니다.
4. 판정식은 `numeric_min <= numeric_raw <= numeric_max` + 텍스트 허용값 일치입니다.
5. 필수값 누락 또는 기준 미설정은 `판정불가`입니다.
6. 자동 로그아웃 시 세션 종료 후 재로그인하면 단계 임시저장을 복구합니다.
7. checksum은 SHA-256(행 정규 문자열 기반)으로 계산합니다.
8. 감사 이벤트 최소 목록은 `LOGIN_SUCCESS, LOGIN_FAIL, LOGOUT_TIMEOUT, CRITERIA_UPDATE, JUDGEMENT_CONFIRM, REPORT_PRINT, AUDIT_EXPORT, DATA_RESET`입니다.

## 구현 단계 (오늘 수업 기준, 약 3.5~4시간)
1. 0:00~0:30: 정적 앱 뼈대(index/styles/js 모듈)와 위저드 라우팅 구성.
2. 0:30~1:15: 저장소 계층(IndexedDB + localStorage 폴백), 고정 admin 로그인, 실패잠금 구현.
3. 1:15~2:00: 기준설정/입력검증/자동판정 엔진(반올림·판정분리 포함) 구현.
4. 2:00~2:40: 판정확정 잠금, 부적합 사유 강제, 임시저장/복구 구현.
5. 2:40~3:20: 보고서 인쇄뷰(PDF), Audit append 및 CSV Export 구현.
6. 3:20~4:00: 시연 시나리오 리허설, 오류 메시지 정리, 체크리스트 검증.

## 테스트 케이스 및 시연 시나리오
1. 로그인 성공/실패, 5회 실패 1분 잠금 해제 동작 확인.
2. 자동 로그아웃(예: 1분 설정) 후 재로그인 복구 확인.
3. 기준 미설정 상태에서 판정불가 처리 확인.
4. 숫자 입력 `12.34` 표시 `12.3`, `12.35` 표시 `12.4` 반올림 확인.
5. 판정 경계값(min/max 정확히 일치) 적합 처리 확인.
6. 텍스트 공백/대소문자 변형 입력이 허용값과 매칭되는지 확인.
7. 부적합 시 사유 미입력으로 확정 차단 확인.
8. 확정 후 레코드 수정 불가(잠금) 확인.
9. 보고서 인쇄뷰에 작성자ID/생성시각/KST 표기 확인.
10. Audit CSV에 시간/사용자/행위/변경내용/checksum 포함 확인.
11. 데이터 초기화 버튼 실행 권한(admin) 및 초기화 결과 확인.
12. IndexedDB 차단 상황에서 localStorage 폴백 경고 및 기능 지속 확인.

## 리스크와 트레이드오프
1. 비밀번호 평문 저장은 보안 리스크가 크며 `교육용 예외`로 명시합니다.
2. 정적 웹앱 특성상 완전 불변 저장은 불가하므로 checksum + 운영 절차(세션 종료 시 백업)로 보완합니다.
3. `showSaveFilePicker`류 UX는 브라우저/보안 컨텍스트 제약이 있으므로 localhost/Chrome·Edge를 표준으로 고정합니다.
4. 계정관리 화면을 제외해 속도는 확보되지만 확장성은 후순위로 남깁니다.

## 가정 및 기본값

4. CSV 학습은 입력 업로드가 아닌 출력(Audit Export) 중심입니다.
